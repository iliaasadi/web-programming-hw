# تمرین عملی HTTP

### ۱. اجرای سرویس فقط روی شبکه داخلی

سرویس قدیمی authentication ندارد. برای استفاده داخل سازمان این موضوع مشکلی نیست، ولی اگر پورتش از اینترنت باز باشد بقیه هم می‌توانند از آن استفاده کنند. پس سرویس می‌تواند روشن باشد، به شرطی که از بیرون به آن پورت وصل نشوند.

اگر فقط همان ماشین به سرویس نیاز دارد، آن را به `127.0.0.1` وصل می‌کنم نه به `0.0.0.0`. حالت دوم روی همه کارت‌های شبکه گوش می‌دهد، حتی کارتی که بیرون از شبکه داخلی است. وقتی چند ماشین داخل سازمان باید سرویس را ببینند، به‌جای این از یک IP خصوصی استفاده می‌کنم.

در Docker هم پورت سرویس را publish نمی‌کنم. httpbin را روی یک شبکه داخلی می‌گذارم و فقط پروکسی عضو همان شبکه است. از بیرون فقط پورت ۸۰ خود پروکسی باز می‌ماند و درخواست‌ها از همان‌جا به سرویس داخلی می‌روند. عدد ۸۰۸۱ در صورت تمرین مثال است. ایمیج `go-httpbin` داخل کانتینر معمولاً روی ۸۰۸۰ گوش می‌دهد و این پورت را هم به host وصل نمی‌کنم.

### ۲. TLS Termination

این قسمت را برای تحویل عملی پیاده نمی‌کنم. چیزی که بالا می‌آید HTTP روی پورت ۸۰ است.

TLS Termination یعنی رمزنگاری سر مرز شبکه، روی reverse proxy، تمام شود. کاربر بیرون با پروکسی HTTPS صحبت می‌کند و گواهی دست پروکسی است. پروکسی درخواست را باز می‌کند و چون مسیر تا سرویس قدیمی داخل شبکه خودمان است، ادامه را با HTTP معمولی می‌فرستد. برنامه legacy معمولاً گواهی را درست نگه نمی‌دارد و برای این کار لازم نیست خودش تغییر کند.

این روش جای JWT را نمی‌گیرد. TLS جلوی خوانده شدن درخواست وسط راه را می‌گیرد، ولی هنوز باید معلوم شود چه کسی اجازه دسترسی دارد. اگر TLS تا خود سرویس قدیمی برود، پروکسی هدر و بدنه را نمی‌بیند و نمی‌تواند JWT را بررسی کند.
